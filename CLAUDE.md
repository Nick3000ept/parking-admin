## Архитектура коротко

- **Auth**: токен в URL `?t=` → localStorage → бэк проверяет на каждый запрос
- **doGet?action=load** возвращает весь снапшот (~1MB JSON: rooms, works, assignments, tip_panels)
- **doGet?action=ping** — диагностика, список всех листов в файле
- **doGet?action=writeLog** — последние 50 строк журнала `Лог_записей` в JSON (только токен Админа/Наблюдателя) — удалённая диагностика «сохранил, а пусто» без открытия таблицы
- **doGet?action=factCheck** — сверка журнала `Факт с админки` с датами в `Главный` (только Админ/Наблюдатель): сколько пар совпало, чего нет в журнале, что лишнее, где разошлись даты, разбивка по работам, до 10 примеров каждого вида. Наружу отдаёт только агрегаты. Пригодится, если пользователь перезальёт журнал или заподозрит расхождение
- **doGet?action=equipStats** — сводка по монтажу: текущий срез (позиций/готово/в работе/не начато) + прогресс за 7 и 30 дней из Журнала_монтажа (позиций с прогрессом, доведено до 100%, прирост в процент-пунктах, разбивка по работам). Показывается блоком вверху окна «Аналитика», кэш на фронте 5 минут
- **doPost** — `setDate` / `clearDate` c hint `{row, colDate, colSp}` для fast-path; `setEquipBatch {items: [{num, work, pct}]}` — пакетная запись процентов монтажа (один Lock, одно чтение листа, запись группами RangeList по одинаковым значениям; лимит 500 позиций); `setEquip {num, work, pct}` — одиночная запись, оставлена для совместимости открытых сессий. Статус бэк вычисляет из процента сам. LockService только на запись.
- **Проценты монтажа копятся в очередь** (как отметки): изменения сразу видны в интерфейсе, в таблицу уходят по большой зелёной кнопке «Сохранить N», закреплённой снизу по центру экрана (решение пользователя 2026-08-24) — счётчик общий с отметками отделки. При ошибке несённое возвращается в очередь / откатывается построчно; закрытие вкладки с несохранённым — предупреждение браузера.
- **Монтаж оборудования в карточке**: блок в попапе у помещений, чьи работы есть в листе `Монтаж_оборудования` (load отдаёт `equip`: num → works[]). Строка блока = работа: название, подрядчик мелким шрифтом, поле процента (0–100); статус выводится цветом строки, «Обновлено» — в подсказке при наведении. Права построчные: Админ и роль «Тех помещения» — всё; подрядчик — строки, где он в колонке «Подрядчик»; Наблюдатель — просмотр. Optimistic UI с откатом, гонка ответов защищена `equipSeq`.
- **Кнопка «Тех помещения»** (в шапке, рядом с «Аналитикой», toggle с подсветкой) — **видна роли «Тех помещения» (`tech`) и Админу** (решение пользователя 2026-08-26, ранее была только у `tech`); у подрядчиков и Наблюдателя скрыта. Роль `tech` видит все помещения, правит только проценты монтажа (по всем помещениям, как админ), отметки отделки бэк ей отклоняет. Кнопка включает отдельный режим: показываются только помещения группы «Тех помещения»; на карточке — конкретное наименование и **работы монтажа с полями процентов прямо на карточке** (без открытия попапа; карточка шире, класс `.card.tech`); вместо чипсов работ в шапке — **категории тех-помещений** (Венткамеры / Электрощитовые / Кроссовые / ИТП / ЦТП / Узлы учёта / КНС / Насосные / ТП / РУ / Вводы КЛ / Прочие — классификатор `roomTechCategory()` по подстроке наименования, single-select). Галочки/зелёный по отделке в этом режиме на карточках не показываются. При входе в режим сбрасывается выбранная работа, при выходе — выбранная категория.
- **Вёрстка шапки корпусов**: после каждой отрисовки `syncHeaderWidths()` копирует в шапку К1..КП4 фактические ширины колонок матрицы (`getComputedStyle(...).gridTemplateColumns`) + пересинхронизация на resize. Без этого при матрице шире экрана колонки распухали от содержимого, а шапка делила ширину поровну — корпуса «съезжали» с накоплением слева направо (баг 2026-09-03, два проявления: тех-режим с широкими карточками и роль, видящая все 16 корпусов). В тех-режиме дополнительно колонки обеих сеток — `minmax(266px, 1fr)`, чтобы были равномерными.
- **Optimistic UI**: клик в режиме отметки моментально красит карточку, fetch уходит параллельно. Race condition защищён через `cellSeq[num|idRaboty]`.
- **Кэш**: `localStorage.parking_data_<token>` с `version_hash` — мгновенный рендер при перезагрузке + фоновое обновление.
- **Надёжность сохранения** (после инцидента 2026-09-03 «сохранил, а в таблице пусто»):
  - Все запросы к GAS (load и postAction) — с 3 попытками и паузами; HTML-ответ
    вместо JSON (GAS периодически отдаёт «Страница не найдена»/404) считается сбоем
    попытки, не тихим успехом.
  - Очередь несохранённого дублируется в `localStorage.parking_queue_<token>` —
    переживает закрытие/перезагрузку вкладки; при входе `restoreQueue()` возвращает
    её и показывает «Сохранить N».
  - Провал отправки целиком — кнопка становится красной «⚠ Не отправлено N» и
    остаётся до успешной досылки; отказ сервера по позициям — модальное окно
    со списком «помещение → причина» (`showSaveErrors`).
  - Свежий снапшот load не затирает внесённое: `applyFreshData()` накладывает поверх
    него подтверждённые в сессии изменения (`sessionConfirms`) и несохранённую очередь.
- **Отметки живут в журнале `Факт с админки`** (бэк @29, 2026-09-08). `setMarks`
  дописывает строку на каждое изменение (снятие — строка с пустой датой), в
  «Главный» не пишет ничего. `loadSnapshot` берёт подрядчика из «Главного», а дату —
  из журнала (последняя строка по паре); пары нет в журнале — читает старую колонку
  даты, если она ещё есть в листе. Одиночные `setDate`/`clearDate` из старых вкладок
  проксируются в `setMarks`; прежние функции прямой записи в ячейку удалены.
  Причина переезда: запись в ячейку периодически не доходила при успешном ответе
  сервера, добавление строк в конец листа не потерялось ни разу.
  Тестовый параметр `factSheet` (POST-тело и `?factSheet=` у `load`) переключает
  журнал на лист для нагрузочных проверок — принимаются только имена, начинающиеся
  с `Факт_тест`, боевой журнал через него не подменить.
- **Запись отметок с контрольным перечитыванием** (`setMarks`, бэк @27, 2026-09-08):
  после `setValue`/`clearContent` и `flush` бэк перечитывает те же ячейки. Не
  подтвердившиеся пишет повторно по одной, снова перечитывает, и если значение так и
  не легло — возвращает по этой позиции `ok: false` («Таблица не подтвердила запись»),
  фронт откатывает карточку и показывает окно с причинами. Раньше бэк считал запись
  успешной по отсутствию исключения: пользователь видел зелёные отметки и «выполнено»
  в журнале, а в таблице было пусто и в истории версий ячейки — ни одного изменения
  (инцидент 2026-09-08). Пустая ячейка определяется через `isEmptyCell_()` — строка
  из пробелов тоже считается пустой.

  штатно. Лечение — контрольное перечитывание в `setMarks` (см. «Надёжность
  сохранения»); по журналу теперь видно колонки «Записано и проверено» /
  «Не подтвердилось».
- **GAS-эндпоинт периодически отвечает HTML-страницей 404 («Страница не найдена»)
  вместо выполнения скрипта** — поймано 2026-09-03: в одну минуту оба токена получали
  404, через 20 минут 5 из 6 запросов проходили. Из-за этого «сохранения» коллег молча
  пропадали (сайт показывал отметки, в таблицу ничего не доезжало). Лечение на фронте —
  ретраи + громкие ошибки + живучая очередь (см. «Надёжность сохранения»). При жалобе
  «сохранил, а пусто» — первым делом смотреть лист `Лог_записей`.
- **Параметр токена различается**: на сайте — `?t=<токен>`, а в прямых запросах к GAS API —
  `?token=<токен>` (напр. `?action=load&token=...`). С `t=` бэк отвечает «Доступ закрыт»,
  что легко принять за устаревший токен.
- При переименовании листов в Sheets — синхронно поменять `CONFIG.SHEET_*` в `script.gs` и `clasp push`.
- Чтобы добавить новую работу: строка в `Ведомость_работ` + две колонки в `Главный`. UI подхватит при F5.
- Чтобы добавить подрядчика: строка в `Ведомость_подрядчиков` со свежим токеном. Имя автоматом попадёт в Data Validation колонок `*СП` (если он настроен).
- `Типы_помещений.Цвет` с 2026-08-25 на карточки НЕ влияет: фон карточки (при не выбранной
  работе) показывает прогресс отделки + процент внизу (готовые назначенные работы / все
  назначенные): 0% — светло-серый, в работе 1–99% — жёлтый (насыщенность по проценту),
  100% — сплошной зелёный с ✓. Колонка «Цвет» в листе оставлена, но код её не читает.
- На бэке имена сравниваются после `.trim()` — защита от trailing-пробелов в Sheets.
- **Даты отметок в «Главный» живут в двух форматах**: настоящие даты (бэк отдаёт `yyyy-MM-dd`)
  и текст `дд.мм.гггг` (~3,5 тыс. ячеек, внесены вручную до/мимо сайта — бэк отдаёт строку
  как есть). Всё, что читает даты на фронте, должно понимать оба формата — хелпер
  `dateToYm()` в index.html. Инцидент 2026-08-11: «Аналитика» считала «Готово» только по
  ISO-датам и показывала 606 м² стяжки вместо ~13 000.
- **НЕ писать тестовые/диагностические значения в дальние пустые ячейки листа «Главный»**
  (напр. столбец 200). Любое значение в дальнем столбце/строке раздувает
  `getLastColumn()`/`getLastRow()`, и после этого `loadSnapshot` (`getDataRange`) и
  `setMarks` (читает весь лист `getRange(1,1,lastRow,lastColumn)`) сканируют раздутый
  диапазон — load и каждое сохранение резко тормозят, вплоть до «Failed to fetch» на
  фронте (браузер обрывает медленный запрос). Реальные данные — колонки A..AD (1..30).
  Для диагностики использовать **отдельный временный лист** или ячейку рядом с данными,
  и **обязательно чистить след** после теста. Симптом раздутия виден в `?action=ping`:
  поле `glavny_info.cols` должно быть ~30, не больше. (инцидент 2026-07-23→24: метка
  `DBG_...` в `GR1` раздула лист до 200 столбцов и затормозила сохранение.)
